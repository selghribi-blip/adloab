# Adloab — لوحة نمو عربية آمنة

هذا المستودع يحتوي على **نموذج ويب محلي جاهز للتجربة** باسم Adloab. صُمّم كبديل مشروع لفكرة لوحة إدارة الزيارات والحملات، لكن بحدود واضحة: يعرض تحليلات لزيارات حقيقية أو بيانات يملكها المستخدم، ولا ينفّذ نقرات أو مشاهدات وهمية ولا يتجاوز أنظمة المنصات.

> **مهم:** لا يمكنني المساعدة في إنشاء شبكة تضخيم مشاهدات/نقرات، حسابات وهمية، تدوير بروكسيات لتجاوز الحظر، تجاوز CAPTCHA، أو أي أداة قد تسبب احتيالاً إعلانياً أو مخالفة لشروط YouTube/TikTok/شبكات الإعلانات. يمكن تطوير هذا المشروع ليكون منصة تحليلات وتسويق شرعية للبيانات المصرح بها.

## ما يعمل الآن

- لوحة RTL عربية متجاوبة للحاسوب والجوال.
- نظرة عامة بمؤشرات KPI، مخطط زيارات، مزيج القنوات، وحملات نشطة.
- صفحة حملات مع بحث، فلاتر حالة، إضافة حملة، تشغيل/إيقاف، وبيانات محفوظة محلياً.
- صفحة تحليلات بمسار تحويل وأحداث نموذجية قابلة للتصدير.
- منشئ UTM يعمل في المتصفح مع زر نسخ الرابط.
- فحص إعدادات محلي لا يفتح المواقع آلياً ولا يولّد زيارات.
- استيراد CSV محلي فقط؛ لا يتم رفع الملف إلى أي خدمة في هذه النسخة.
- صفحة مصادر بيانات تجريبية لـ GA4 وSearch Console وPostHog وMatomo.
- قائمة ثقة وامتثال توضّح الموافقة، الاحتفاظ، الصلاحيات، وما لا يفعله المنتج.
- إعدادات التفضيلات والوضع الليلي وحذف بيانات `localStorage`.
- تصدير CSV للحملات والأحداث.
- إشعارات، نوافذ منبثقة، رسائل نجاح/تحذير، وقائمة جوال.

البيانات المعروضة حالياً **بيانات تجريبية** وليست بيانات حقيقية من ad4you أو من حساباتك.

## التشغيل السريع

لا يحتاج النموذج الحالي إلى Node أو قاعدة بيانات:

```bash
cd adloab
python3 -m http.server 4173 --bind 0.0.0.0
```

ثم افتحي `http://localhost:4173` في المتصفح. ويمكن استخدام أي خادم ملفات ثابت مثل Live Server أو Caddy.

الملفات الأساسية:

- `index.html` — الهيكل واللغة العربية وRTL.
- `styles.css` — التصميم المتجاوب والنسق الليلي.
- `app.js` — الحالة، التفاعلات، النوافذ، التخزين المحلي، والتصدير.

## ما يلزم قبل الإنتاج

هذه النسخة Prototype أمامي وليست نظاماً متعدد المستخدمين. لإطلاقها كمنتج حقيقي، نفّذي البنود التالية:

1. **مصادقة وصلاحيات:** أضيفي خادماً مع جلسات آمنة، أدواراً (مالك/محرر/مشاهد)، حماية CSRF، وتحديد معدل الطلبات. لا تعتمدي على `localStorage` للصلاحيات.
2. **قاعدة بيانات:** انقلي الحملات والمصادر والأحداث إلى PostgreSQL أو خدمة مُدارة. أضيفي migrations، فهارس، وسياسة احتفاظ وحذف.
3. **OAuth والخادم:** اربطي GA4 وSearch Console وPostHog/Matomo من الخادم فقط. لا تضعي `service_role key` أو مفاتيح الدفع أو أسرار OAuth في `app.js` أو داخل المتصفح.
4. **استقبال الأحداث:** استخدمي endpoint موثوقاً مع schema validation، منع التكرار، توقيع webhooks، وسجل تدقيق. اجمعي أقل قدر ممكن من البيانات الشخصية.
5. **الامتثال:** أضيفي بانر موافقة مناسباً للمنطقة المستهدفة، سياسة خصوصية وشروط استخدام، وآلية حذف/تصدير بيانات. راجعي قوانين بلدك وشروط كل منصة وإعلان.
6. **المدفوعات والخطط:** نفّذي الاشتراكات عبر Stripe أو Paddle من الخادم مع webhooks والتحقق من الحالة. لا تخزّني أرقام البطاقات بنفسك.
7. **المراقبة والنسخ الاحتياطي:** أضيفي Sentry أو بديلًا، سجلات بلا أسرار، نسخاً احتياطية مشفرة، وفحص dependencies وتحديثاتها.
8. **اختبارات:** اختبارات وحدة للتجميع والتقارير، E2E لإنشاء حملة وتصدير CSV، واختبار صلاحيات لكل دور.
9. **الأمن:** أضيفي CSP، HSTS، `X-Content-Type-Options`، سياسة iframe مناسبة، تحققاً من رفع CSV، وحداً لحجم الملف. لا تعرضي بيانات شخصية في سجلات التحليلات.
10. **تغيير بيانات العرض:** استبدلي `initialCampaigns` وبيانات المخططات في `app.js` باستدعاءات API حقيقية مع حالات loading/error/empty.

## مصادر مجانية مناسبة

تحققي من الأسعار والحدود الحالية قبل الاعتماد على أي خطة، لأنها تتغير:

- **GitHub Pages:** استضافة مجانية للواجهة الثابتة: <https://pages.github.com/>
- **Cloudflare Pages:** استضافة للملفات الثابتة مع نشر من Git: <https://pages.cloudflare.com/>
- **Vercel:** نشر الواجهة ومشاريع JavaScript الصغيرة: <https://vercel.com/docs>
- **Supabase:** PostgreSQL ومصادقة وواجهات API؛ استخدمي RLS ولا تضعي مفتاح الخدمة في الواجهة: <https://supabase.com/docs>
- **Neon:** PostgreSQL مُدار مناسب للتجارب: <https://neon.tech/docs>
- **PostHog:** تحليلات وأحداث للمنتج مع خطة مجانية محدودة حسب الاستخدام: <https://posthog.com/docs>
- **Matomo:** بديل مفتوح المصدر، ويمكن استضافته ذاتياً: <https://matomo.org/docs/>

## خيارات مدفوعة اختيارية

ليست مطلوبة لتشغيل النموذج الحالي. عند الحاجة فقط، قارني الخطط الرسمية لـ:

- قاعدة بيانات/Backend مُدار: Supabase Pro أو Neon أو Render.
- استضافة: Vercel Pro أو Cloudflare Plans.
- أخطاء ومراقبة: Sentry.
- تحليلات المنتج: PostHog أو Matomo Cloud.
- مدفوعات: Stripe أو Paddle.

اختاري أقل حزمة تكفيك، وراجعي تكلفة التخزين، طلبات API، السجلات، والنسخ الاحتياطية قبل الاشتراك.

## نموذج معماري مقترح

```text
واجهة Adloab (Vite/React أو هذا النموذج الثابت)
          │ HTTPS + جلسة مستخدم
API خادم (Node/Fastify أو Python/FastAPI)
          ├── PostgreSQL + migrations + RLS/roles
          ├── OAuth adapters لـ GA4 / Search Console / PostHog
          ├── Webhook verifier + event ingestion
          └── Stripe/Paddle webhooks
```

ابدئي بالواجهة الحالية، ثم أضيفي مصدراً واحداً حقيقياً (GA4 مثلاً) واختبريه بحساب تملكينه قبل إضافة أي مصدر آخر. لا تربطي ملفات ad4you التنفيذية أو مشاريع غير موثوقة مباشرة بهذا التطبيق؛ افحصي الترخيص والكود والاعتمادات، ولا تشغّلي ملف `.exe` مجهولاً على جهازك الرئيسي.
